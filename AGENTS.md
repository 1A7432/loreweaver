# AGENTS.md — contributor & AI-agent guide

Loreweaver is a self-hosted **AI Game Master / Keeper** for tabletop RPGs: a world/story-first engine (structured world + module + rules + persistent state), not a persona-chat frontend. Terminal-first over Iroh p2p, system-agnostic (D&D 5e SRD + CoC 7e), English-first with runtime `en`/`zh` i18n, MIT. This file orients humans and AI coding agents working in the repo — it is the single source of truth (CLAUDE.md just imports it). User-facing docs live in `README.md`; the open client protocol in `docs/protocol.md`; the extensibility contract in `docs/plugins.md`. The formats themselves are specified in `docs/lwf/` (LWF, CC BY 4.0): a change to a pack/card/rulepack/hook/panel format updates the matching `docs/lwf/formats/*.md` in the same commit.

## This branch: the 3.0 rewrite
`v3` rebuilds Loreweaver on Bun in strict TypeScript as a new project: protocol 3.0, no compatibility with 2.x (wire, database, pack and module formats), SillyTavern card import kept. Everything below this section describes the **2.6 Python server, which is frozen**: read it as the reference, do not change it (`core/ infra/ agent/ gateway/ net/ adapters/ app.py`), and do not add anything for the sake of matching it. It is deleted when 3.0 ships. CI on this branch does not run the Python tests; the `frozen` job fails instead if any frozen file differs from `main`.
- New code: `server/` (one package; the layers are directories under `server/src/` — `infra < core < agent < gateway < net`, plus `cli/` and `worker/`) and `sdk/` (the module SDK). The workspace root is the repository root (`package.json`, `bun.lock`); `clients/protocol` and `clients/tui` are members.
- `server/test/architecture/imports.test.ts` holds the import rules: layer direction; Bun-specific APIs (`bun:*`, the `Bun` global) only under `server/src/infra/runtime/`; nothing reachable from `worker/` imports the database; relative imports name their `.ts` extension.
- TypeScript is strict with erasable syntax only (`tsconfig.base.json`): no enums, namespaces or parameter properties.
- Protocol 3.0's frames are `clients/protocol/src/v3/frames.ts` (imported as `loreweaver-protocol/v3`); the 2.6 files beside it serve the not-yet-migrated TUI.
- The store is synchronous (`server/src/infra/store.ts`): a turn suspends only at a model call, a room-worker exchange or outbound network, and holds no room state across one.
- Content code runs in the room's worker (`server/src/worker/`), never on the main thread. A module answers through effects; the engine validates and applies them (`server/src/agent/modules.ts`).
- User-facing text comes from `server/locales/{en,zh}/*.json` through `server/src/infra/i18n.ts` — the new server's own catalogs, apart from the frozen tree's `locales/`.
- Every write to a room goes through a `RoomWriter` bound to the room's generation and a turn (`server/src/infra/store.ts`); undo, reset, import and delete bump the generation and an older writer is refused. A background lane keeps the `RoomContext` it was scheduled with (`server/src/agent/context.ts`) and commits in one synchronous block — never fetch a fresh writer when a lane finishes.
- Room content is documents; `project(document, viewer)` is the only way content leaves toward a connection (`server/src/core/documents/`). Build a view by picking named public fields, and give every type a sentinel test (a marker in each non-public field must not appear in a view it does not belong to). Whole stored documents (`core/documents/raw.ts`) are for `core/` and `agent/` only.
- Names, ids, titles and keys that come from packs, cards or players are content: hold them in `Map`s or ordered pair lists (an object reorders number-like keys and has `constructor`/`__proto__`), count characters in code points, use the `u` flag for anything that may be CJK, parse numbers strictly, and cap every list and string with a named constant — over the cap is refused with a coded result, never truncated silently.
- Results are data with stable codes; nothing in `server/src` writes a sentence a person reads. Text for people comes from a catalog: each area keeps `server/locales/{en,zh}/<area>.json` and a `catalog.ts` beside its code, and calls `translate(catalog, locale, key, params)`. Text written FOR THE MODEL is of two kinds: prompts that exist in both languages because the model answers in the room's language (the Keeper's, an NPC's, the fold's) are catalogs too, carried over unchanged from the tuned originals; instructions that exist only in English (tool descriptions, the Scribe's and the Director's prompts, a corrective re-ask) live as constants beside the code that sends them.
- A Keeper turn is one function, `runKeeperTurn` (`server/src/agent/turn/engine.ts`; its header lists the steps and where each may suspend). The room (`server/src/gateway/room.ts`) owns the lock, the connections and what follows a turn — views, idle, the Scribe and the Stage Director on an ordered chain no turn waits for. The two agree only through `server/src/agent/turn/types.ts`: the engine never sees a connection, the room never sees a prompt.
- Only a line of speech allocates a turn. A command runs under the room's lock in arrival order with speech, opens no turn, and its writes belong to the latest turn. Undo, reset and import do not wait for the lock; whatever the old generation still has in flight ends as `stale` by itself — never build cancel-and-wait.
- Model calls: every `.chat(` call site is listed with its lane in `server/test/architecture/model_lanes.test.ts`; a new one fails the build until it is listed. One Keeper turn is at most 21 calls (3 fold batches + 12 tool rounds + 5 check rounds or 1 finalizer + 1 overflow re-send), held by `server/test/agent/turn/budget.test.ts`; a player turn adds 1 Scribe and, on a beat, 1 Director. `genchar` and a player's character import make one authoring call each (`agent/lanes/genchar.ts`, the Keeper's client, no re-ask) outside any turn and outside the room's lock; they are capped per member by `GENCHAR_PER_HOUR`, not by the turn budget.
- What the prompt consumes from the room (the Scribe's whispers, pending module facts, the record of players' commands) is cleared in the turn's final commit block, by value — never when read.
- A new document type is added to `server/src/core/registry.ts`; a new server-lifetime part is wired in `server/src/cli/compose.ts`, which `serve` and the compiled self-test both go through.
- Content reaches a server as a pack (`docs/lwf/formats/pack.md`, manifest 3): `server/src/infra/zip.ts` is the security boundary of installation, `server/src/core/packs/` validates a whole pack as data, and only the OPERATOR installs (`loreweaver install` — a module is real code in the server's process); room admins enable what is installed. Panels are fed by views and nothing else (`server/src/core/panels/`; `instantiate` in the protocol package is the one evaluation every client shares).
- The wire has one description: `docs/protocol.md`, written from the code and amended with it. A protocol change lands in `clients/protocol/src/v3/` (types, decoder, the reference `Session`), the server, the document, and `server/test/net/client_roundtrip.test.ts` — the test that wires the real client to the real server session and compares their logs — in one change.
- The terminal client (`clients/tui`) has one source of server data, the protocol package's `Session` snapshot; no component keeps a copy of a view or of the log.
- A live-model run (`server/eval/playtest.ts`, logs under the ignored `playtest/`) is how behaviour is checked: a judge of secrecy, the dice-first rule, and a probe of every tool call. One session at a time.
- Directories named `cards/` or `modules/` are ignored by `.gitignore` everywhere in the repository; do not create one.
- Check: `bun install` at the root, then `bun run check` in `server/` and in `sdk/` (type check AND tests); `bun run build` in `server/` compiles the single-file server and runs its self-test (a real turn over a scripted model). Run it: `bun server/src/cli/main.ts serve` (`key <room> <role> <name>` hands out access keys; `pack` / `install` / `packs` / `uninstall` handle packs; `import-world <room> <card-file>` brings a SillyTavern card in from the shell); settings are `TRPG_*` variables, read in `server/src/infra/config.ts` only. Play it: `cd clients/tui && bun run dev`, then "Host locally & play". If your npm registry is a mirror, install with `--registry https://registry.npmjs.org/` so `bun.lock` does not record mirror URLs.

## Architecture (layers, each with one job)
- `core/` — **deterministic engine** (never AI-generated), rule-AGNOSTIC since M16: dice, `resolution` (pack-compiled check ladders + the QuickJS `rules_script` lane), `sheets` (pack-declared sheet shapes: canonical-name bridges, derived DAG — derived values are NEVER persisted — vitals, wire resources), `character_rules` (pack-constraint validation on every stat write path), clock, `rulepacks` (data-driven rule systems: resolution/sheet/subsystems/commands/expertise all pack data; `tests/architecture/` pins agent/ to zero system tokens), `skills` (SKILL.md loader), deterministic relationship tracks, `modvars` (deterministic module-variable trackers), worldbook, `charcard` (SillyTavern-card parser), `table_habits` — the M20 E procedural-memory type (how THIS table plays; keeper-side only, player projection returns None, index-only residency), `chronicle` — the M18 campaign-history types (`chronicle`/`campaign_summary`/`thread`: projections keep keeper annotations out of every player-grade view) plus the deterministic fold policy (0.60 trigger / 0.40 floor / 0.85 emergency, 4-turn no-future lag window), and `documents` — the M17 meta-type: ALL room content (lore/NPCs/sheets/pregens/modvars/MVU tree/notes/pools) is a `Document` in one table, and every type's `project(doc, viewer)` is THE single wire chokepoint for iron rule #3.
- `infra/` — plumbing: SQLite store (`documents` + `room_state` + kv tables — content documents, room-scoped runtime state, non-room leftovers), pydantic-settings config + hot runtime overrides/credential book, i18n, `llm`/`embeddings` (each with a `Fake*` offline double), vector, `providers` (multi-vendor LLM factory).
- `agent/` — the AI-KP brain: `AgentCtx`, `tools` (`@tool` schema-gen + gating), `kp_tools*` (the Keeper tools), `forge` (self-extension generators: skill/rulepack/module from a description), `prompt_builder`, `loop` (function-calling loop), `services` (the wiring bundle), `chronicle` (the M18 fold flow: batch-fold old chronicle records into the rolling `campaign_summary` when the usage meter crosses the trigger; folded records join the embedding index for topical recall — records themselves are AUTO-WRITTEN since M21 by the Scribe, one player-grade line per material turn at zero extra model calls, so durable memory and the history trim that rides on it never depend on the Keeper remembering `record_chronicle`; the keeper spoiler margin stays exclusive to that voluntary tool), knowledge-scoped `npc`/`companion` actors, and the three model-driven prep lanes that used to sit in core/ — `module_initializer` (full-text module analysis into the keeper/player pools), `document_manager` (chunking + RAG answers), `char_from_persona` (persona → rule-legal sheet; the validation half stays in `core.character_rules`).
- `gateway/` — platform-independent: session/events/turn/member/room state, `commands/` (dual-dialect + slash — a package: `router` owns the spec table and dispatch, each domain is a mixin module `checks`/`sheet`/`rules`/`rooms`/`cast`/`world`/`panels`/`media`/`llm`/`forge`; a new command lands in its domain module plus one spec row, never in the turn pipeline), `ops` (rate-limit/censor/permissions), `hub` (the cross-transport RoomHub), `director`.
- `net/` — `session` (transport-agnostic SessionCore), `iroh_server` (p2p QUIC, the DEFAULT carrier), `tui_server` (WebSocket, offline-test/loopback only), `keystore`, `admin`, `room_backup`.
- `adapters/` — `cli` only (the local operator REPL). The five chat-platform adapters (Discord/QQ/Telegram/Feishu/OneBot) were REMOVED 2026-07-30: the UI direction is protocol clients with a deeply customizable UI extension layer (`ui` frames, panels), which text-chat platforms structurally cannot render. Don't re-add platform adapters; build against `docs/protocol.md` instead. The QQ path is a protocol client, the terminal client's bridge mode (official Bot API first, OneBot second).
- `clients/` — TypeScript: `protocol` (shared types + `WsClient`; published to npm as `loreweaver-protocol`, whose `major.minor` tracks the wire-protocol version), `tui` (OpenTUI terminal client; `IrohClient` and the one-click host live here). Both speak `docs/protocol.md`. The DESKTOP client — Loreweaver Studio, Tauri (Rust transport + React UI), play mode with tier-1/tier-2 panels and the keeper screens plus the card/pack studio — lives in the separate `loreweaver-studio` repo and is the recommended player client; it consumes `loreweaver-protocol` from npm and pins itself to the engine with a cross-repo round-trip gate (`bun run roundtrip` there). Changing the protocol or a pack format here means that gate must be rerun there. Bumping the protocol means bumping it in all five places at once — `net/session.py` (the authority), `protocol/src/types.ts`, the npm manifest's version + description, `protocol/README.md`, `docs/protocol.md` — pinned by `tests/architecture/test_protocol_version_sync.py`.

## Iron rules / red lines (do not break)
1. **Deterministic vs generative split.** Dice, success levels, character math, random tables, permissions, censorship = real code. Narration / NPCs / flavor = the model. Never AI-ify the deterministic core.
2. **Dice-first.** A check rolls real dice, then narrates the outcome per the success level — never pre-write the result.
3. **Information isolation (anti-metagaming).** Player knowledge and each NPC/companion's private knowledge are scoped by construction: an NPC/companion actor is built from ONLY its own record + sheet (never the keeper pool). Structurally this is the M17 document projection contract — every outbound surface consumes `core.documents.project(doc, viewer)` views (secret lore, NPC secrets, keeper-only modvars and unexposed MVU leaves never cross a player-grade projection; sentinel tests in `tests/documents/`). The main Keeper holds the FULL module truth by design and permanently — a keeper who learns the answer late cannot foreshadow, plant clues, or keep a mastermind coherent, which is why every published module hands the keeper everything up front. This asymmetry is deliberate and is NOT a gap awaiting a structural fix: never propose scoping, tiering, or staging keeper knowledge, not even as an experiment. Keeper restraint (never quoting keeper-only material to players) is a BEHAVIORAL property, and the live-model evals are its correct and final guarantee. The card split (拆卡) is part of this rule: world machinery in an imported card — hooks, `[InitVar]` schemas, EJS — reaches a room only through the keeper's `.import … world` (player imports strip it structurally, `core.card_split`), and imported MVU variable leaves ship to player panels only after keeper exposure (`.var expose`). Keeper-side ANNOTATIONS of imported lore — the M26 `lore_overlay` document behind `.lore enable/bind` and a pack's `overlay:` file — are keeper-only documents (player projection `None`) and never ride a player import. Both the structural tests and behavioral gates are red lines; keep them green.
4. **English-first + i18n, no hardcoded natural language.** Identifiers/comments/commits in English. Every user-facing string goes through `infra.i18n` + `locales/{en,zh}/*.json` (client-side: the typed `tt()`/`messages` dict in `clients/tui/src/i18n.ts`, both languages). `scripts/i18n_lint.py` gates this. (CJK game-DATA — skill names, aliases — is exempt, like the existing data modules.)
5. **Single prompt assembly, per lane.** The KEEPER's context has exactly one assembler and one caller: every segment the Keeper sees — the `core.prompt_sections` builders, world lore, the preset layer, the imported world card's directives, skill bodies, hook injections, scribe whispers, the chronicle — is assembled in `agent/prompt_builder.py`, returned as ONE object, and sent by `agent/loop.py` alone; no other module builds or extends Keeper context. Every OTHER model call is a declared lane with its own scoped assembler: the knowledge-scoped actors (NPC, companion, Director, Scribe — each prompts from its own record, which IS iron rule #3), the chronicle fold (memory), and the authoring/prep lanes (forge, module analysis, RAG answers, persona→sheet). `core/` makes no model calls at all. `tests/architecture/test_model_call_lanes.py` pins all of it: a new `.chat()` call site fails the build until it names its lane, which is the moment to ask whether it should exist. How the Keeper object lands on the wire (one system message, or a stable system message plus a trailing state message) is an implementation detail chosen for cache behavior, NOT a rule — the invariant is one assembler per lane, not the message count.

## Per-turn model-call budget
ONE player turn is worst-case **~155 model calls**; a new model-driven lane has to fit inside that, and adding one means updating this number and `tests/agent/test_turn_call_budget.py`. Per KP turn (`agent/loop.py`): ≤3 chronicle folds + `max_rounds` 12 tool rounds + 5 end-of-turn check rounds (`agent/turn_checks.MAX_ROUNDS_PER_TURN` — one Stop-form runner over a rulepack-declarable table, clamped so a content pack cannot lengthen a turn; or instead the 1 tools-disabled max-rounds finalizer) + 1 **context-overflow retry** (M23 WS2 — a provider that refuses the prompt as too long triggers a recovery fold and ONE re-send, only if that fold actually folded records; the fold itself is not a new term, because `fold_for_overflow` spends what is left of the same ≤3 batches) = **21**. A player turn adds 1 Scribe pass and, on a beat only, 1 Director call (plus imagegen: 1 image + `pregen_per_beat` warmed in the background), then up to `MAX_COMPANION_TURNS` 6 companion sub-turns of 1 actor call + a nested KP turn each. Companion sub-turns run NO Scribe/Director of their own — that guard is structural, in three places (`gateway/turn.py` ×2, `gateway/director.py`). The one UNBOUNDED term: each `speak_as_npc` / `companion_act` the model emits costs a sub-call, and nothing caps how many it emits per round. A whole player turn occupies its room: `hub.turn_lock(session_key)` is a per-room `asyncio.Lock` taken at the TRANSPORT CHOKE POINTS (`net/session.py`, `gateway/runner.py`), so concurrent input on one room queues in arrival order (the lock's waiters are FIFO) while other rooms run freely. `run_kp_turn` and the companion director deliberately do NOT take it — that is what keeps a nested companion/director sub-turn from self-deadlocking. Do not confuse it with `hub.begin_turn`/`end_turn`, which lock nothing: they are the nesting counter that decides when the room publishes busy/idle. The occupancy includes retry sleeps: `infra/llm_retry.py` retries 3× with up to 20s backoff (up to 60s when honoring a provider's cooldown hint) and COMPOSES with the SDK's own retries (only the ChatGPT client passes `max_retries=0`; the OpenAI-compatible, Anthropic and Gemini clients do not), so one logical call can be 9 HTTP attempts. The Scribe/Director pass is the one lane outside the lock: `agent/scribe_coord.py` keeps at most one ordered chain per room, so same-room passes land in the order they were scheduled, and undo/reset/import/delete/load cancel-and-drain that chain before mutating. NO turn waits on it — a turn that parked on the previous turn's Scribe + Director + image would simply hand the table that latency one turn later. After the pass, the latest chronicle-turn snapshot is refreshed unless the chronicle counter has moved past the turn the pass was scheduled on (a newer turn owns that boundary).

```bash
uv sync --extra anthropic --extra gemini --extra ejs   # env + deps; the `dev` group (pytest/ruff) installs by default; `ejs` = QuickJS-sandboxed full SillyTavern EJS templates (tests skip without it). (pip fallback: python3 -m venv .venv && . .venv/bin/activate && pip install -e ".[dev,anthropic,gemini,ejs]")

uv run ruff check core infra agent gateway net adapters app.py lw_versioning.py scripts
uv run python scripts/i18n_lint.py    # NO ARGS (passing a path wrongly scans .venv)
uv run python -m app --cli     # try it: r 3d6+2 / /roll 4d6kh3 / .ra 侦查 / .setcoc 2
uv run python -m app --doctor  # sanity-check locales/rulepacks/skills discovery
# clients: cd clients/<protocol|tui> && bun install && bun test
```

## How to extend
- **Rule system** → add a `rulepacks/<system>.yaml` (defaults/derived/alias/st_show/set_keys + optional per-locale `display` names); no code change for data-driven parts.
- **KP skill** → a `skills/<id>/SKILL.md` (Claude-Code shape: YAML frontmatter `name`/`description`/`allowed-tools` + Markdown body); per-room enable via `.skill enable <id>`. An optional sibling `hooks.js` adds sandboxed turn-lifecycle event handlers (Layer C.1 — see `docs/plugins.md`).
- **Content pack** → bundle a whole work (skills + rulepacks + cards + lorebooks + panels + presentation kit + prompt presets + prep scripts + assets) as one `.lwpack` zip with a `pack.yaml` manifest: `python -m app --pack <src-dir>` to build, `--install <path|https|gh:owner/repo[@tag]> [--yes]` to install (Git releases ARE the registry; see `docs/plugins.md`). Cards declare `kind: world|character` (enforced against real payload detection); a bundled rulepack may patch a base system via `extends:`. While AUTHORING a pack, skip the build loop entirely: `.dev mount <src-dir>` (keeper command, confined under `TRPG_DEV__SOURCE_ROOT`, off unless set) live-reloads the source tree into a sandbox room on every save (`gateway/dev_room.py`; `docs/authoring.md` §8). `python -m app --lint <src-dir>` is the ADVISORY pack check (`core/pack_lint.py` — deterministic, never fails a build; also printed by `--pack`, and sent after every dev-room reload): it reports only what the engine's own rules make certain, and a new check needs its message key in `MESSAGE_KEYS` plus both `locales/*/pack_lint.json` catalogs. Its findings are KEEPER-GRADE text (they name secret entry titles and keeper-side variables): in a room they go to the mounting admin alone (`gateway.dev_room.send_lint`), never into a broadcast reply — iron rule #3.
- **LLM provider** → most vendors work via the OpenAI-compatible path + a `PRESETS` entry in `infra/providers.py`; add a native class (see `AnthropicLLM`/`GeminiLLM`) only for non-OpenAI APIs.
- **KP tool** → an `async def name(self, ctx, ...) -> str` decorated `@tool` on a provider class; add the provider to `agent/kp_tools.build_kp_toolset`. Bulk prep work can also be scripted: `run_prep_plan` (prep phase only) runs sandboxed JS that emits an operation LIST, and the engine applies each entry through this same `@tool` path — `core/prep_script.py`. Flag secret-reading tools `keeper_only=True`; flag skill-unlocked tools `gated=True`; flag bulk/low-frequency ones `prep_only=True` so the play phase drops them (M20 B — `agent/tool_phase.py` decides which phase a room is in, `.phase` pins it, and `tests/architecture/test_tool_phase_budget.py` holds the play-phase schema budget); flag a tool whose calls for DIFFERENT values of one argument touch different documents `concurrent_by="<arg>"` (`speak_as_npc` by `npc`: the loop runs such calls of one round together with read-only ones, in call order, and serializes everything else — see `agent/loop._concurrency_groups`); flag a tool that only works against a store some rooms lack `needs="<capability>"` (`agent/tool_phase.room_capabilities`, recomputed per turn — a world-card room has no module pool, so pool tools are not offered there). Unmarked means available in both phases and every room.
- **Client** → build against `docs/protocol.md` (the versioned WS/Iroh protocol) + reuse `loreweaver-protocol` types.
- **Room-scoped state** (a new `room_state` key, document type or vector lane) → declare a `RoomStateFacet` in the module that WRITES it and list that module in `net/room_lifecycle.FACET_MODULES` (M23 WS1 — `infra/room_facets.py`). The facet says which `.reset` scope kills it, or why it survives every scope; `tests/architecture/test_room_facets.py` fails the build on state no facet claims. The registry answers WHAT to clean — `net/room_backup.py` still owns the ORDER and ATOMICITY of the four lifecycle operations.

## Working conventions for AI agents
- **Parallelize leaves, serialize the merge.** Independent new modules can be built + tested in isolation concurrently; the wiring into shared files (`build_kp_toolset`, `services`, `commands`, `prompt_builder`) is one careful sequential pass.
- **Scope your test runs.** When others may be editing concurrently, run only your module's tests, not the whole suite.
- **NEVER foreground a blocking server** (`python -m app --serve`, a dev server) — it hangs. Verify via tests (they spin up ephemeral in-process servers); background + `timeout` + `kill` if you truly must.
- **Decision records:** check `docs/notes/rejected/` BEFORE proposing a mechanism in its territory — rejections are binding; a non-trivial change adds or updates a note in `docs/notes/` in the same PR.
- **Before lifecycle/locking/provider/replay work,** read `docs/defensive-patterns.md` — the paid-for rules live there.
- **After any change:** `uv run ruff check` + `uv run python scripts/i18n_lint.py` + `uv run pytest -q` (and the relevant `bun test`) must all pass.
