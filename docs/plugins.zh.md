# 扩展 Loreweaver

> Loreweaver 3.0 的扩展契约（客户端协议 3.0，扩展包清单 3）。一步步做扩展包见 [authoring.zh.md](authoring.zh.md)；卡见 [cards.zh.md](cards.zh.md)；编写模组见 [sdk/README.md](../sdk/README.md)（英文）。各项格式在 [LWF](lwf/SPEC.md) 里规定，客户端协议见 [protocol.zh.md](protocol.zh.md)。

Loreweaver 是一个以世界和故事为先的 AI 守秘人，不是一个和人设聊天的前端。它想成为社区来扩展的平台，而不是一份人人都要 fork 的代码。这份文档讲哪些东西可以扩展、怎么进入服务器，以及服务器信任什么。

## 指导原则：沿用惯例，不发明惯例

社区已经有格式的地方，Loreweaver 直接读：

| 需求 | 沿用的惯例 |
|---|---|
| 人物、世界书 | 酒馆人物卡 V1/V2/V3（JSON 和 PNG）及其 `character_book` |
| 卡里的变量和模板 | MagVarUpdate 的 `[InitVar]` 和 `<UpdateVariable>`；ST-Prompt-Template 的 EJS 接口 |
| 给守秘人的指示 | Claude Code 的 `SKILL.md`（YAML 头部加 Markdown 正文） |
| 分发 | Git Release：挂在 Release 上的 `.lwpack` 可以用 `gh:owner/repo` 安装 |

没有现成惯例的，是 Loreweaver 自己的格式，公开写在 LWF 里：原生卡、规则包、面板、演出包、扩展包容器和模组约定。

## 哪些东西可以扩展

一切都装在**扩展包**里进入服务器：一个 `.lwpack` 压缩包，带一份 `pack.yaml` 清单（清单 3：[pack.md](lwf/formats/pack.md)）。

| 扩展 | 是什么 | 数据还是代码 | 在房间里 |
|---|---|---|---|
| **卡**（`cards`） | 酒馆卡或原生 `*.lorecard.json`：设定、变量、模板、人设 | 数据；设定条目可以是 EJS 模板 | 由房间管理员（世界）或玩家（角色）导入——[cards.zh.md](cards.zh.md) |
| **规则包**（`rulepacks`） | 用 YAML 写的规则系统：角色卡结构、检定怎么掷怎么判、派生值、子系统、命令；通常是补丁（`extends: coc7`） | 数据 | 全服务器共用；房间用 `rule system` 选一个——[rulepacks.md](lwf/formats/rulepacks.md) |
| **技能**（`skills`） | `SKILL.md`：技能开启期间守秘人读到的文字，以及它解锁的受限工具 | 数据 | 每个房间用 `skill enable` 开启——[skills.md](lwf/formats/skills.md) §1 |
| **面板**（`panels`） | 故事旁边的界面，数据来自视图；模板，或带模板 fallback 的自包含 HTML 页面 | 数据（页面只在客户端的沙箱框架里运行） | 扩展包启用后即打开；`panels disable` 逐个关——[panels.md](lwf/formats/panels.md) |
| **演出包**（`presentation`） | 演出导演能展示和播放什么：风格、带参考图的对象、音效 | 数据 | 扩展包启用后并入房间的演出包和音频库——[pack.md](lwf/formats/pack.md) §4.2 |
| **模组**（`modules`） | 基于 `loreweaver/module` 的 TypeScript 或 JavaScript：事件处理、命令、逐人计算的视图、角色、时钟 | **代码** | 扩展包启用后在房间的工作线程里加载——[sdk/README.md](../sdk/README.md) |

内置的有：规则系统 `coc7`、`dnd5e`、`wod`，技能 `image-gen`、`mature-mode`、`romance-relationships`。

## 数据和代码

Loreweaver 守住一条线：**骰子、成功等级、角色数值、权限和保密归代码；叙事归模型。** 每种扩展都在这条线的某一边。

- **数据**在安装前整体校验：每个规则包都要能编译，每个技能和每张卡都要能解析，每个面板文件都要通过面板检查，每张图片都得是它扩展名说的那种文件。规则包用一门封闭的表达式语言描述机制；规则包里没有任何东西作为代码运行。
- **模组是代码。** 它通过**效果**回应引擎——事实、变量写入、掷骰、界面区块——由引擎校验、限量、执行；模组从不直接调用引擎。要让整桌信得过的骰子，走 `fx.roll`，也就是引擎的骰子。
- **模板是内容代码。** 设定条目里的 EJS 在房间的工作线程里作为 JavaScript 运行，有时间上限，时钟固定，随机数有种子。它的写入只是请求，由引擎执行。

## 信任模型

**模组作为普通代码在服务器进程里运行，没有沙箱。** 它能用文件系统、网络和它打包进来的任何东西。服务器保证的是故障隔离：模组抛错或卡住，只让它的房间少一次调用，不会拖垮服务器，也不会连累别的模组。安装一个带模组的扩展包，就是决定运行它的代码。

所以：

- **只有运营者或房间管理员能安装。** 运营者在命令行里装（`loreweaver install <来源>` 显示信任卡，加 `--yes` 才安装，加 `--force` 替换 id 和版本都相同的已装扩展包，不加则拒绝）。房间管理员在聊天里装（`pack install <来源>`），同时在那个房间启用。同一个安装器，同样的检查。在聊天里安装扩展包的房间管理员，就是在决定服务器运行什么代码：管理员钥匙只给你愿意把服务器交给他的人。
- **先看信任卡。** 写下任何东西之前，服务器根据校验过的内容算出一份摘要给你看：扩展包是否运行代码、有哪些模组（文件、大小、sha256），它的规则系统、技能和技能解锁的工具，卡和每张卡带的世界机制，面板和它们读的视图，演出包、资源，以及被忽略的东西。它是算出来的，不可能少报扩展包里有什么。
- **安装不等于启用。** 从命令行安装不改变任何房间。房间管理员启用一个扩展包（`pack enable <id>`），只有那个房间会拿到它的模组、演出包、面板、技能和卡。
- **没有装依赖这一步。** 模组的依赖在构建时就打包进去；安装扩展包时服务器不会去下载或安装任何东西。
- **压缩包是一道安全边界。** 路径受限（不能有 `..`、绝对路径、链接、设备名），解压时就按上限计量，扩展包里唯一允许的代码是声明过的模组打包文件：出现任何别的脚本文件，整个扩展包拒收。
- **模板是管理员的选择。** 卡里的模板只有在房间管理员把它作为世界导入之后才会运行，和酒馆一样：你的牌桌，你的卡。

## 信息隔离

玩家不能知道他们的角色还不知道的事。3.0 在结构上保证这一点：

- **视图由服务器逐人计算。** 客户端从不做过滤。秘密设定条目、只给守秘人的变量、导入变量树里没公开的叶子、世界卡的正文和指令，永远不会出现在玩家的视图里。
- **模组视图由模组逐人计算**（`for(who, room)`）：只返回这个人能看的东西。服务器只把它转给这个人。
- **面板只显示看的人自己的视图。** `visible_when` 只是把区块藏起来，不是保密——区块照样送到能看到这个面板的每个人。`audience: admin`，或者读了 `admin/*` 视图，会让面板只给管理员看。
- **拆卡靠代码。** 玩家的角色导入只写一个角色和一个座位；世界机制只能通过管理员的世界导入进入房间，守秘人调用不了它。
- **守秘人的机关只归守秘人。** `role: "keeper"` 的模组命令从不列给玩家；守秘人用 `run_command` 工具运行它，房间管理员也能运行它来纠正错误。

守秘人本身按设计掌握一个世界的全部真相：晚知道答案的主持人没法埋伏笔。不在叙事里泄露只给守秘人的材料，是一种行为，由真模型评测来检验。

## 名字和顺序

- **id 归第一个占用者。** 扩展包的规则系统和技能并入服务器的；内置的在先，然后是已安装的扩展包，按安装顺序。后来的扩展包里 id 已被占用的规则系统或技能不会加载，安装时会点名。
- **模组 id 按房间算。** 模组的命令和视图叫 `<模组>/<名字>`。同一个房间里启用的两个扩展包不能有同 id 的模组（`module_id_taken`）。一个房间的模组按扩展包启用的先后被调用。
- **面板**叫 `<扩展包>/<面板>`，音效叫 `<扩展包>/<音效>`。

## 版本

- 扩展包写 `manifest_version: 3`；3.0 服务器拒收 1 和 2。
- `engine: { protocol, server }` 是最低版本；服务器更旧就拒绝安装（`engine_too_old`）。扩展包之间没有依赖：一个扩展包自带它需要的一切，规则包只能扩展内置系统或同一个扩展包里的规则包。
- 安装一个扩展包的新版本会替换旧版本；启用了它的房间会重新加载，跑新版本，模组从保存的状态开始。
- 客户端协议单独定版本（[protocol.zh.md](protocol.zh.md)）；协议包 `loreweaver-protocol` 跟着它走。

## 3.0 里没有的

这些 2.x 有，3.0 没有：

- 技能或卡里的 **`hooks.js`** 回合生命周期脚本，以及运行它们的 QuickJS 沙箱。扩展包里的 `hooks.js` 会被忽略并报告；卡里的钩子脚本只计数，绝不运行。对回合作出反应的代码就是模组。
- **准备阶段脚本**和准备阶段；**提示词预设**；作为单独种类的**世界书**（设定放在卡里）；扩展包的设定**覆盖层**文件。
- 规则包里的**规则脚本通道**；需要它的规则包加载不了。
- **锻造**（从一段描述生成技能、规则包或模组）、带热重载的**开发房间**，以及**检查**命令：作者重新构建、重新安装（[authoring.zh.md](authoring.zh.md) §2）。
- **AI 同伴**和原生卡可认领的 **pregens**。
- 任何其它形式的服务器插件：模组是加代码的唯一方式。
