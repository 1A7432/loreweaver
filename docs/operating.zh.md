# 开服带团

*给开服的人看的：模型怎么选、账单怎么控、战役怎么不丢。*

这一篇讲的是**怎么把一局团运营好**。要搭一台常驻服务器——systemd、钥匙落盘、信任模型——那是 [deploy.zh.md](deploy.zh.md)，两篇配着看。

---

## 1. 模型

Loreweaver 在**五条车道**上调用模型，各干各的活。把每条车道配对尺寸，是影响质量和成本最大的一个杠杆。

| 车道 | 什么时候跑 | 默认 | 适合 |
|---|---|---|---|
| **守秘人**（KP） | 每回合 | `TRPG_LLM__*` | 你愿意付钱的最强模型 |
| **NPC** | 守秘人让某个 NPC 亲自开口时 | 用守秘人的 | 会写的模型；它只看得到这个 NPC 自己的档案 |
| **书记官**（Scribe） | 每回合，回复之后 | 用守秘人的 | 小、便宜、快的模型 |
| **演出导演**（Director） | 只在剧情节拍上 | 用守秘人的 | 和守秘人同一个模型——节拍少，拼的是品味 |
| **记忆** | 编年史折叠时 | 用守秘人的 | 摘要老实的模型 |

守秘人之外的每条车道都用同一套设置，换个前缀就行：`TRPG_NPC__*`、`TRPG_SCRIBE__*`、`TRPG_DIRECTOR__*`、`TRPG_MEMORY__*`。一条车道只写了模型（或推理强度），就沿用守秘人的接口和密钥；写了服务商或 base URL，就是一个单独的接口，要配自己的密钥。房间管理员的「模型」屏会列出每条车道，也会标出哪几条「与守秘人相同」。

### 守秘人

```dotenv
TRPG_LLM__PROVIDER=deepseek
TRPG_LLM__API_KEY=sk-…
TRPG_LLM__CHAT_MODEL=deepseek-v4-pro
TRPG_LLM__REASONING_EFFORT=max
```

**这里别省。** 守秘人做什么都靠工具调用——掷骰、查卡、写追踪器、推时钟。指令遵循强的模型会老老实实掷真骰子、守着模组走；便宜模型会直接说“你成功了”，一次检定工具都不调，还会跑出剧本。在我们自己的测试里，这是好团和烂团之间最稳定的差别。

`openai`、`anthropic`、`deepseek`、`openrouter`、`moonshot` 是预设。别的接口，自己起个名字再给出地址就能用——`TRPG_LLM__PROVIDER=<你起的名字>` 加 `TRPG_LLM__BASE_URL`——走三种接口之一（`TRPG_LLM__WIRE`）：`openai-compatible`（Chat Completions，默认）、`anthropic`（Messages API）、`openai-responses`（OpenAI 的 Responses API）。

**服务器不认识的模型，要设上下文长度**：`TRPG_LLM__CONTEXT_WINDOW`。服务器认识核对过的那些模型的上下文长度；别的模型一律按 32,000 token 算，并在启动时说出来（`context_window_unknown`）。编年史折叠就拿这个数当分母，数不对，房间要么摘要得太早，要么太晚。

切换是热的——不用重启，玩到一半也行：

```
.model                                     看每条车道现在用的什么（只有你看得到）
.model list [provider]                     这台服务器认识的服务商；带上一个，就列它的模型
.model set <provider> [model] [key=…] [base_url=…] [wire=…] [effort=…] [context=N] [lane=…]
                                           切换一条车道（默认是守秘人那条）
.model key <key> [lane=…]                  给这条车道当前的服务商存一个密钥
.model reset [lane]                        恢复成服务器自己的设置
.imagegen                                  看生图接口（只有你看得到）
.imagegen set <provider> [model] [size] [key=…] [base_url=…]
.imagegen off                              不再生图
```

模型设置**对整个服务器生效**：每个房间都跟着走。密钥**按服务商记住**，切回用过的服务商不用再填；回复里的密钥一律打码显示。下一回合就换成新模型；正在进行的回合用它开始时的那个模型跑完。这些在管理员客户端的「模型」屏里也都能做，密钥填在隐藏的输入框里——这样更稳妥，因为命令词打错一个字，那一行就会变成你在桌上说的话。

### 书记官——小模型，真活

书记官默认开着，每个守秘人回合之后多跑一次调用，在房间的锁之外跑，谁也不用等它。它拿叙事去对模组的追踪器（要引原文为证，引不出来的它不能写），把判断悄悄递进守秘人的**下一**回合（“好像过了一天”、“刚才那段恐怖场面也许该过一次理智检定”），给这一回合写一行编年史，再把这回合的剧情节拍分好类交给导演。

`TRPG_SCRIBE__*` 不设，就沿用守秘人的客户端——能用，但等于每一回合都按旗舰价付记账的钱。给它配一个自己的小模型：

```dotenv
TRPG_SCRIBE__PROVIDER=deepseek
TRPG_SCRIBE__CHAT_MODEL=deepseek-v4-flash
TRPG_SCRIBE__API_KEY=sk-…
TRPG_SCRIBE__REASONING_EFFORT=low
```

`TRPG_SCRIBE__ENABLED=false` 关掉它。关之前想一想它为什么存在：一次真实实测里，一个叙事很强的模型跑完了整个模组，一次都没碰过状态层——追踪器停在初始值，剧情已经往前冲了三天。开着书记官重跑同一个模组，追踪器跟着故事走了。记账这件事，靠模型自觉是靠不住的。

### 演出导演——可选，而且三件事得同时点头

演出导演负责在剧情节拍上布置舞台：幕卡、信笺、剪报、音频提示、生成图。它默认用**守秘人**的模型，和书记官的建议正好相反——节拍少，拼的是品味。

**只有内容包要它，它才会醒**：只在启用了带演出资料包的内容包的房间里跑。没有这种内容包的牌桌永远叫不醒它，也不会为它花钱。要生图，还得这三件事同时点头：

1. `TRPG_DIRECTOR__IMAGES`（默认开），
2. 配好了生图接口——`.env` 里的 `TRPG_IMAGEGEN__*`，或者运行时用 `.imagegen set`（模型屏里的「设置生图服务…」也行），
3. 内容包自己的资料包——作者要是写了 `generation: pack_only`，那是作者的决定，你这边怎么设都盖不过它。

```dotenv
# TRPG_DIRECTOR__ENABLED=true
# TRPG_DIRECTOR__CHAT_MODEL=          # 不设 = 用守秘人的客户端
# TRPG_DIRECTOR__IMAGES=true
# TRPG_DIRECTOR__MAX_IMAGES=24        # 一段故事最多生成几张图
# TRPG_DIRECTOR__PREGEN_PER_BEAT=2
```

超过 `MAX_IMAGES` 之后，导演照样布置舞台，只用内容包自带的图和已经生成过的图，不再花钱。另外，守秘人自己的生图工具每个房间每小时最多 10 张。

### 本地模型

提示不能离开你这台机器的时候，把守秘人指向一个本地的 OpenAI 兼容接口（Ollama、LM Studio、vLLM……）：`TRPG_LLM__PROVIDER` 写一个你自己起的名字，`TRPG_LLM__BASE_URL` 写它的地址，接口不看密钥的话 `TRPG_LLM__API_KEY` 随便填一个非空值，再设上它的 `TRPG_LLM__CONTEXT_WINDOW`。给哪条车道配了单独的接口，那条也照样改。只有这样配，守秘人专属设定和玩家输入才会留在你自己掌控的机器上——光是自己托管*服务器*，并不会让模型流量变成本地的。

## 2. 配额、延迟和 token 账单

### 看顶栏

终端客户端的顶栏上是上一回合的数字：

```
● · 上回合 ↑2.0k ↓120 · 缓存 75%
```

- **`↑` / `↓`**——守秘人最近一回合读进去、写出来的 token。一场下来盯着 `↑` 看：它会随着故事变长，编年史折叠时应该会掉回来（见下文）。
- **`缓存`**——这次提示里有多大比例是从服务商的提示缓存里取的。越高越便宜越快。健康的长团这个数一直很高；要是它反复塌下去，说明每回合提示的前缀都被打破了。

### 提示为什么这么排

守秘人的提示被刻意分成**稳定的头**和**多变的尾**。身份、规则系统的专长、互动风格、世界卡的指令、启用的技能、模组的命令目录和滚动的战役摘要放在前面，很少变；设定、实时状态、未收的线头、召回的记录，以及其他会动的东西放在后面。在支持显式提示缓存的服务商上，两者之间的分界就是一个缓存断点。

战役摘要虽然会变，还是放在前面，因为它只在折叠时才变——而折叠本来就会停止重放它吸收掉的那些回合，那一回合的缓存反正保不住。其他回合，它都直接从缓存里读。

对你的实际影响是：**任何改动头部的操作都会让整段缓存失效**。换模型、开关技能或内容包、玩到一半导入世界，都会这样，而且都合情合理——只是要预期下一回合缓存不中，别每隔几回合就随手来一下。

### 服务商限流的时候

每一次模型调用，遇到 429 或过载都会带抖动、有上限地退避重试：总共三次，每次最多等 20 秒。被限流的回合会**变慢，但不会死**。服务商明说了要等多久的，就等那么久，最多 60 秒；要等更久，就不再重试，免得一直占着房间。要是回合经常变慢，说明这桌的节奏超过了你套餐的速率限制。第一步不是升级套餐，而是给书记官（还有导演，如果你开了）配它们自己更小的模型和密钥，别和守秘人共用。

### 战役记忆会自己折叠

长团总会比任何上下文窗口活得久。跑团过程被记成编年史文档；当拼出来的提示超过模型上下文窗口的 **60%**，最老的记录成批折叠进滚动的战役摘要，直到降回 **40%** 以下。还有一条 **85%** 的紧急线：到了就在下一次调用前强制折叠——这条线的作用是保证折叠调用本身总有余量。最近 **4** 个回合永远不折：正在演的戏还不算能摘要的历史。要是服务商还是以“太长”拒绝了提示，服务器会折叠一次再重发一次——前提是这次折叠真的腾出了地方。

用的是比例，不是绝对 token 数，所以多大的窗口行为都一样：

```dotenv
# TRPG_CHRONICLE__ENABLED=true
# TRPG_CHRONICLE__FOLD_TRIGGER=0.60
# TRPG_CHRONICLE__FOLD_FLOOR=0.40
# TRPG_CHRONICLE__FOLD_EMERGENCY=0.85
# TRPG_CHRONICLE__LAG_TURNS=4
# TRPG_CHRONICLE__SUMMARY_MAX_CHARS=4000
```

默认值刻意放在编程 agent 做压缩的那个区间里偏激进的一头，因为叙事比代码好摘要得多，而且跑团每一回合都要把上下文重发一遍——成本、延迟、上下文腐化，都跟你让它保持多满成正比。

管理员可以这样看：

```
.chronicle             列出记录
.chronicle summary     滚动的前情摘要
.chronicle threads     未收的线头：埋下的伏笔、已经上膛的后果
.chronicle note <文字>  加一条守秘人一侧的批注
.recap                 玩家看到的样子：同一段故事，剧透批注已去掉
```

`.chronicle` 只回给你自己，因为里面可能有守秘人的批注；`.recap` 是同一批文档投影之后、给玩家看的安全版本。

**小窗口模型：** 能缩的只有可折叠的那一部分。如果在一个上下文很小的模型上，固定部分——系统提示、世界卡、技能——本身就超过了下限，折叠会尽力而为，房间还是满的。这是模型和内容的尺寸问题，不是折叠的 bug；解决办法是换窗口更大的模型，或者少往头部放东西。

### token 到底花在哪

大致上，每一回合：一次守秘人调用，每多一轮工具调用再多一次（大，前缀大多命中缓存；一回合最多 21 次），守秘人每让一个 NPC 开口就一次，一次书记官调用（小模型、小提示），只在节拍上再加一次导演调用。折叠偶尔才有。账单吓到你的话，按这个顺序查：（1）书记官是不是在用守秘人的模型？（2）`缓存` 是不是很低？（3）折叠的触发线是不是调高了，或者上下文长度设得太大了？

## 3. 别把战役弄丢

### 东西都放在哪

所有东西都在服务器的数据目录里：`TRPG_DATA_DIR`，默认是启动服务器时所在目录下的 `./data`。用「本地开服并开玩」拉起来的服务器，数据在 `<本地服务器目录>/data`——默认是 `~/.loreweaver/data`。

| 东西 | 放在 | 当成什么对待 |
|---|---|---|
| 战役状态（所有房间）、在聊天里设的模型和密钥 | `loreweaver.db` | 战役本身——也是一个密码文件 |
| 访问钥匙 | `keys.json` | 密码文件 |
| 服务器的身份（ticket） | `transport.key` | 留着，不然 ticket 会变 |
| 图片、音频、团报页面 | `media/` | 战役本身 |
| 已安装的内容包 | `packs/<id>/<版本>/` | 可以重装 |

### 备份

最靠得住的备份就是最笨的那种：停掉服务器，把整个数据目录复制一份，再启动。

一个房间也可以导出成一份存档：`.save`（或 `.save export`；终端客户端里按 `Ctrl+Shift+S`）会把整个房间回给发起的管理员——只给他，因为里面有这个房间的全部秘密。`.save import <存档>` 用一份存档替换整个房间；之后每个成员的连接都会断开，重新连回来就是房间现在的样子。终端客户端目前还不会把导出的存档写成文件，所以现在还是复制数据目录吧。

### 撤销和重置——不用重新发钥匙就能重来

`.undo [回合数]` 把整个房间往回倒——故事，以及那个回合开始之后跑过的每一条命令——倒一回合或几回合，最远到 `TRPG_STORE__UNDO_DEPTH`（默认 4）。

重置是**原地**重开一局：钥匙、在线连接和房间设置（语言、房规、启用的技能）都保留，谁都不用重新邀请。三种范围，都是先预备、再确认：

```
.reset            只清故事和进度；角色保留
.reset chars      清故事和角色
.reset all        全部清掉，连房间的媒体一起
.reset confirm    执行预备好的重置——要在 60 秒内
```

**不会自动备份**——可能还要的话，先自己备一份。每个客户端都会收到一个 `reset` 事件，它也会清空本地的聊天记录，所以重新开始在每块屏幕上看起来都是干净的。

### 更新

3.0 没有自更新。从源码跑的服务器要更新：停掉，`git pull`，`bun install`，再启动。ticket 不会变。客户端和服务器的协议主版本号必须一致：太旧或太新的客户端会被拒绝，并告诉你是哪一边落后了。

## 4. 一张简短的开团检查单

开团前：

- 看服务器的就绪那一行：`notes` 里出现 `model_not_configured`、`context_window_unknown` 或 `recall_off`，就是字面意思。
- `.model`——服务商对不对，密钥还能不能用。
- `.pack`、`.panels`、`.skill`——模组的内容包、它的面板和守秘人技能是真的**启用**了，而不只是装上了。
- 上一场要紧的话，复制一份数据目录。

进行中：

- 时不时扫一眼 `↑` 和 `缓存`。`↑` 应该是锯齿形，而不是一路往上涨。
- 命令的回复只给发命令的人；只有事件——叙事、掷骰、演出——才会到桌上。要是守秘人级别的内容（`.npc show`、`.chronicle`、`.var`）出现在了桌上的日志里，那是值得报的 bug。
- `.npc` 是你管房间演员表的手：列出来，`show <名字>` 看完整档案（人设、暗中的目的、这个 NPC 知道什么），守秘人临场编了一个你不想要的，就 `delete <名字>`。
- `.bot off` 让守秘人先闭嘴，你好处理事情；`.bot on` 再放它回来。

结束后：

- `.report` 看这一场的计分板。
- `.report html` 把整场团报做成一个自包含的网页，发给要它的那个客户端（每个玩家都可以要自己的一份）；`.report html reveal` 是管理员的复盘版，把对玩家藏起来的东西也印出来——只发到你自己的连接。终端客户端把两种都存到 `~/.loreweaver/reports`。
- `.chronicle` / `.recap`——核对一下账本和实际发生的事对不对得上。要是哪个追踪器落后了，或者跑到了剧情*前面*，那正是书记官要抓的那类问题，值得开一个 issue。
