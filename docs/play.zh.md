# 玩家上手：五分钟

*给玩家看的。如果你是开服那个人，这份也建议先看——你也要玩——然后再看[开服带团](operating.zh.md)。*

玩之前不用先背一套指令。你就用平常说话的方式讲你的角色要做什么，剩下的守秘人会接。下面这些是为了让牌桌“看得懂”：你自己想掷骰的时候怎么掷，怎么判断算不算成功，以及屏幕角落那些数字是什么意思。

---

## 1. 进房间

Loreweaver 3.0 还没有发布版本，所以客户端要从仓库源码里运行（见 [README](../README.zh.md#1-取代码)），机器上需要装好 [Bun](https://bun.sh)：

```bash
cd clients/tui && bun run dev
```

桌面客户端 Loreweaver Studio 的 3.0 版本（它仓库的 `v3` 分支）还没有发布，先用这个终端客户端。在连接界面里，把房间管理员发你的两样东西贴进去：

- **ticket**——服务器的 p2p 地址，一长串，以 `endpoint` 开头；
- **钥匙**——只属于你的那一把。它同时也是你的身份，这里没有账号，也没有密码。

起个昵称，回车。掉线会自己重连并接上原处，所以咖啡馆的 Wi-Fi 抽风一下，损失是几秒钟，不是这一场。连接界面会记住你连过的服务器，点一下就能重新填好。

> Windows 上如果界面看着不对劲——边框错位、颜色发花、鼠标点不动——多半是落在老式控制台里了。请在 **Windows Terminal** 或 **WezTerm** 里运行客户端。

## 2. 建角色

在主菜单打开「我的角色」。不管角色从哪条路来，规则都会校验这张卡：系统不允许的数值会被拉回范围内，并且会告诉你。

| 路子 | 说明 |
|---|---|
| **新建角色** | 服务器按规则系统自己的建卡规则掷出一个；你选系统，想的话再起个名字 |
| **认领现成角色** | 拿一个房间里可认领的角色——比如内容包自带的预设角色 |
| **导入角色卡** | 酒馆卡，PNG 或 JSON 都行——只导入角色本身，细节见 [cards.zh.md](cards.zh.md)；卡表按本房间的规则系统掷，配了模型的话会往卡里人设的方向偏 |
| **按描述生成** | 输入 `.genchar <描述>`（“一个冷静的医生，来调查港口的失踪案”）：模型拟一个人物方向，数值由骰子和规则系统来定 |

同一屏还能改卡、改名、重算生命等资源、放弃或删除角色。在输入框里，可认领角色是这几条：

```
.pc                    看可认领的角色，以及谁在扮演谁
.pc claim 顾晚棠        把这个角色拿过来当你的
.pc release            还回去
```

## 3. 六件值得先知道的事

**自己掷骰。** `.r`（或 `/roll`）吃任意骰点表达式：

```
.r 3d6+2
⚄ Alice 3d6+2 11
```

`4d6kh3` 取最高三个，`2d20kl1` 取最低一个，`5d6!` 爆炸骰，`7d10>=8` 数成功数。`.rh` 掷法一样，但结果只回给你自己。

**发起检定。** `.ra`（`/check`）拿你卡上的技能掷，按你们这桌在跑的规则系统结算：

```
.ra spot hidden
⚄ Alice 1d100 13 vs 25 -> Success
```

前面加一个难度词就是抬高门槛——要压过的目标值变小，这一行显示的就是实际对比的那个目标值（这里侦查是 70）：

```
.ra hard spot hidden
⚄ Alice 1d100 13 vs 35 -> Extreme Success
```

技能名两种语言的别名都认：`spot hidden`、`spot`、`notice`、`perception`、`侦查`、`侦察`、`发现`，指的是同一个技能。

**看等级，别只看数字。** 成功等级由规则系统自己那张档位表决定，不是引擎写死的。CoC 7 版下一次 d100 检定是这么分的：

| 结果 | 意思 |
|---|---|
| 大成功 | 出目 1 |
| 极难成功 | 掷进了技能值的五分之一以内 |
| 困难成功 | 掷进了一半以内 |
| 成功 | 不超过技能值 |
| 失败 | 超了 |
| 大失败 | 技能值低于 50 时掷出 96–100，或者出目 100 |

高档位不只是“更成功”——模组完全可以把一条线索专门卡在“困难成功”上。这也是为什么那一行要把档位打出来，而不是只说过没过。换一个规则系统，档位和用词都会变，因为这张表是跟着系统一起发的数据。

**一次没过应该推动故事，而不是卡住它。** 要是失败之后你不知道该干嘛，就说你改试什么。被逼到一个更差的方案上，是游戏在正常运转，不是游戏坏了。

**你的卡。** `.st` 看，`.st <名字>=<数值>` 改：

```
.st 力量=60             = 就是把这个数写进去
.st HP-=4              -= 是减，+= 是加
.st 力量60 敏捷50        骰娘的连写，一次写几项
```

数值也可以写骰子。你写进去的每一个数都会拿规则系统校验一遍：系统不允许的数值，谁要求的都会被拉回范围内，并且会告诉你。

**回顾剧情。** `.recap` 打印到目前为止的故事，不带剧透：

```
.recap
```

这份前情提要是从战役编年史里出来的，用的是同一套投影——就是让别的秘密不会到你客户端的那一套。守秘人关于“你们错过了什么”的批注，结构上就不在里面。中途加入的人，从这儿补课。

## 4. 屏幕

```
┌─ 已加入 main · 场景 ◷ 黄昏 · 轮次 2 ──────── ● · 上回合 ↑2.0k ↓120 · 缓存 75% ─┐
│                                                    │ 侧栏                       │
│  故事日志——叙事、NPC 对白、                        │ 队伍 · 你的角色 · 场景     │
│  掷骰结果、模组发的手作物                          │ 状态量 · 模组面板          │
└────────────────────────────────────────────────────┴────────────────────────────┘
  > 输入行动或命令
```

- **顶栏**放着房间、场景、游戏内时钟和战斗轮次、连接状态，以及上一回合的 token 数：`↑` 是守秘人读进去的，`↓` 是它写出来的；`缓存` 是这次提示里有多大比例是从服务商的提示缓存里取的，越高越省。
- **侧栏**显示谁在桌上和先攻顺位、你自己的角色、场景和它已确立的事实、你能看的状态量，以及模组自带的面板——节庆日程、潮位表、案情板之类。面板画的是服务端发给你的那份数据，所以不该给你看的东西不会出现在那儿。需要更强客户端才能画的面板，会用一行字说明。
- **图片**——手作物、立绘——直接出现在日志里。按 `Tab` 切到图片，再按 `Enter`（或直接点击）查看；终端画不出来的，会用系统的看图程序打开。有些模组真的会把线索藏在图里，这是故意的。按 `F8` 可以把你自己的图分享给全桌。
- **声音**——房间的音乐、环境音和音效，通过你电脑上的播放器放（mpv、ffplay、afplay、paplay 或 aplay）。`F9` 静音。

## 5. 按键

| 键 | 作用 |
|---|---|
| `?` | 打开／关闭帮助浮层 |
| `Esc` | 回主菜单 |
| `PgUp` / `PgDn` | 滚动故事日志；到顶再按 `PgUp` 加载更早的记录 |
| `↑` / `↓` | 翻你自己之前打过的内容 |
| `Tab` | 切换焦点：输入框 → 选项按钮 → 图片 → 队伍名单 → 面板 → 输入框 |
| `F1`–`F5` | 主题：lamplight · df16 · phosphor · amber · paperwhite |
| `F6` | 窄终端下显示／隐藏侧栏 |
| `F7` | 命令列表——能输入的所有命令和用法 |
| `F8` | 向全桌分享一张图 |
| `F9` | 开关声音 |
| `Ctrl+S` | 把这一场的日志存成文件（`~/.loreweaver/transcripts`） |
| `Ctrl+L` | 清屏（只清你本地的显示，服务端的战役还在；到顶再按 `PgUp` 能重新显示） |
| `Ctrl+C` | 复制选中内容；没选中东西时是退出。macOS 上不一样：按住 `Option` 拖选，`Cmd+C` 复制，这两个键归终端管 |

## 6. 你可能真的会用到的指令

`.help`（或 `F7`）会列出你们这桌所有可用的指令。玩家常用的是这些：

| 指令 | 作用 |
|---|---|
| `.r <表达式>` | 自己掷骰 |
| `.rh <表达式>` | 暗骰，只有你看得到 |
| `.ra <技能>` | 技能检定 |
| `.ra 困难 <技能>` | 抬高难度的检定（英文写 `hard`） |
| `.rav <技能>, <另一个技能>` | 对抗检定，在有这条规则的系统里 |
| `.st` | 看卡 |
| `.st <名字>=<数值>` | 改一项（会校验） |
| `.sc <成功>/<失败>` | 理智检定，在有这套子系统的规则里——比如 `.sc 1/1d6` |
| `.ri` | 看先攻顺位；`.ri roll` 掷先攻进入顺位 |
| `.pc` | 可认领的角色 |
| `.genchar <描述>` | 按描述生成一个角色 |
| `.<模组>/<命令> {…}` | 模组自己的命令，参数写成 JSON——你们这桌的模组提供了哪些，看命令列表 |
| `.recap` | 不带剧透的前情提要 |
| `.report` | 这一场的计分板 |
| `.report html` | 整场团报的网页版，自包含，只发给**你自己**的客户端——终端客户端把它存到 `~/.loreweaver/reports`，用浏览器打开 |
| `.report html reveal` | 仅管理员：复盘版，把对玩家藏起来的东西也印出来，只发给管理员自己的连接 |
| `.jrrp` | 今日人品。没有任何机制作用 |
| `.draw` | 从洗好的一副牌里抽一张 |

两套写法同时生效：骰娘系的中文写法（`.ra 侦查`、`.st 力量50`、`.sc 1/1d6`）和 Avrae 系的英文写法（`/roll 4d6kh3`、`/check`）。你手熟哪套就用哪套。全量参考——包括管理员那一侧的——在[协议的命令表](protocol.md#68-the-engines-commands)。

## 7. AI 能对你做什么，不能做什么

值得知道，因为这会改变你怎么玩：

- **它没法假掷骰。** 每一次检定都走骰子引擎。守秘人负责把结果讲成故事，但结果不是它挑的。
- **它没法偷偷改你的卡。** 每一次写入都要过规则系统的校验，不管是你要求的、管理员要求的，还是模型自己想改的。
- **NPC 没有天眼。** 一个 NPC 是只拿它自己的档案和卡表拼出来的，所以它不可能知道从没给过它的秘密。守秘人本身不一样：它是看得见模组秘密的（不看就主持不了谜案），我们只是要求它别说出来。最后这一点是行为约束，靠真模型实测去量，不是结构上的保证。如果哪次守秘人明显把不该给的东西塞给了你，那是个值得报的 bug。
- **骰子不管剧情需不需要。** 你是会输的，而紧张感有很大一部分就来自这里。
