# 玩家上手：五分钟

*给玩家看的。如果你是开服那个人，这份也建议先看——你也要玩——然后再看[开服带团](operating.zh.md)。*

玩之前不用先背一套指令。你就用平常说话的方式讲你的角色要做什么，剩下的守秘人会接。下面这些是为了让牌桌“看得懂”：你自己想掷骰的时候怎么掷，怎么判断算不算成功，以及屏幕角落那些数字是什么意思。

---

## 1. 进房间

装一个客户端（见 [README](../README.zh.md#1-装客户端)）：推荐 **Loreweaver Studio** 桌面应用——图形界面、实时面板、守秘人那几屏都在里面；**终端客户端**一行命令装好、有终端就能跑。打开 Studio，或运行 `loreweaver`，然后把守秘人发你的两样东西贴进去：

- **ticket**——服务器的 p2p 地址，一长串，以 `endpoint` 开头；
- **邀请码**——只属于你的那一个。它同时也是你的身份，这里没有账号，也没有密码。

起个昵称，回车。掉线会自己重连并接上原处，所以咖啡馆的 Wi-Fi 抽风一下，损失是几秒钟，不是这一场。

> Windows 上如果界面看着不对劲——边框错位、颜色发花、鼠标点不动——多半是落在老式控制台里了。请在 **Windows Terminal** 或 **WezTerm** 里运行 `loreweaver`。

## 2. 建角色

建卡屏给四条路，但它们最后都汇到同一个地方：规则要校验这张卡，不合规的存不进去，不管它是从哪条路来的。

| 路子 | 说明 |
|---|---|
| **自动掷骰** | 按这个系统自己的建卡公式掷属性 |
| **手填** | 你自己写数字，超预算的当场就填不进去 |
| **描述生成** | 写一句话（“一个冷静的医生，来调查港口的失踪案”），AI 拟一张，然后规则再过一遍 |
| **导入卡** | 酒馆 V2/V3 卡，PNG 或 JSON 都行，细节见 [cards.zh.md](cards.zh.md) |

如果守秘人导入的模组自带预设角色，那还有第五条路：认领一个。

```
.pc                    看模组的角色池，以及谁认领了谁
.pc claim 顾晚棠        把这个角色拿过来当你的
.pc release            还回去（卡表会恢复成原样）
```

## 3. 六件值得先知道的事

**自己掷骰。** `.r`（或 `/roll`）吃任意骰点表达式：

```
.r 3d6+2
Roll: 3d6+2 = [4, 4, 1]+2 = 11
```

`4d6kh3` 取最高三个，`2d20kl1` 取最低一个，`5d6!` 爆炸骰，`7d10>=8` 数成功数。`.rh` 掷法一样，但结果只回给你自己。

**发起检定。** `.ra`（`/check`）拿你卡上的技能掷，按你们这桌在跑的规则系统结算：

```
.ra spot hidden
Check Spot Hidden: target 25 (effective 25), roll 13 -> Success
```

前面加一个难度词就是抬高门槛——要压过的目标值变小，这一行也会把它写出来：

```
.ra hard spot hidden
Check Spot Hidden: target 70 (effective 35), roll 13 -> Extreme Success
```

技能名两种语言的别名都认：`spot hidden`、`spot`、`notice`、`perception`、`侦查`、`侦察`、`发现`，指的是同一个技能。

**看等级，别只看数字。** 成功等级由规则系统自己那张档位表决定，不是引擎写死的。CoC 7 版下一次 d100 检定是这么分的：

| 结果 | 意思 |
|---|---|
| 大成功 | 出目 1 |
| 极难成功 | 掷进了技能值的五分之一以内 |
| 困难成功 | 掷进了一半以内 |
| 成功 | 不超过技能值 |
| 失败 | 超了 |
| 大失败 | 技能值低于 50 时掷出 96–100，或者出目 100 |

高档位不只是“更成功”——模组完全可以把一条线索专门卡在“困难成功”上。这也是为什么那一行要把档位打出来，而不是只说过没过。换一个规则系统，档位和用词都会变，因为这张表是跟着系统一起发的数据。

**一次没过应该推动故事，而不是卡住它。** 要是失败之后你不知道该干嘛，就说你改试什么。被逼到一个更差的方案上，是游戏在正常运转，不是游戏坏了。

**你的卡。** `.st` 看，`.st <技能>=<数值>` 改（如果守秘人允许改的话）：

```
.st 力量=60             = 就是把这个数写进去
.st HP-=4              -= 是减，+= 是加
.st mod=-3             想写负数，只能用 = 这种写法
.st STR60              老的连写形式照样能用
.st spot hidden 70     拼出来的英文别名也可以（注意中间的空格）
.st 侦查70              规范名当然可以
```

老写法里数值前面的 `+`/`-` 表示增减（`HP-4` 是减四），所以要直接写一个负数就得用 `=`。一条 `.st`
只用一种写法，别在同一条命令里把 `=` 和连写混着用。

你写进去的每一个数都会拿规则系统校验一遍。系统不允许的数值，谁要求都改不进去。

**回顾剧情。** `.recap` 打印到目前为止的故事，不带剧透：

```
.recap
```

这份前情提要本身是一份守秘人可以编辑的文档，而给你看的那一版是同一套投影生成的——就是让别的秘密不会到你客户端的那一套。守秘人关于“你们错过了什么”的批注，结构上就不在里面。中途加入的人，从这儿补课。

## 4. 屏幕

```
┌─ ◷ 03:12 · 场景 · 第 2 轮 ─────────── ● 在线 · 上下文 34% · 缓存 71% ─┐
│                                                    │ 侧栏             │
│  故事日志——叙事、NPC 对白、                        │ 队伍名单         │
│  掷骰结果、模组发的手作物                          │ 你的资源条       │
│                                                    │ 模组面板         │
└────────────────────────────────────────────────────┴──────────────────┘
  > 在这里打字
```

- **顶栏**放着游戏内时钟和场景、战斗轮次、连接指示灯，以及这桌的 token 花销。`上下文` 是守秘人的上下文窗口现在用了多满；它涨上去之后，引擎会自己把旧历史折叠成摘要，你不用管。`缓存` 是这次提示里有多大比例是从服务商的提示缓存里取的，越高越省。
- **侧栏**显示谁在桌上（AI 同伴也算）、你自己的生命值这类资源条，以及模组自带的面板——节庆日程、潮位表、案情板之类。面板画的是服务端发给你的那份数据，所以不该给你看的东西不会出现在那儿。
- **媒体**——手作物、立绘、地图——直接出现在日志里。选中之后按 `o` 用系统的看图程序打开。有些模组真的会把线索藏在图里，这是故意的。

## 5. 按键

| 键 | 作用 |
|---|---|
| `?` | 打开／关闭帮助浮层 |
| `Esc` | 回主菜单（在主菜单里按没有效果，那已经是最外层） |
| `PgUp` / `PgDn` | 滚动故事日志 |
| `↑` / `↓` | 翻你自己之前打过的内容 |
| `Tab` | 切换焦点：输入框 → 行内选项按钮 → 队伍名单 → 输入框 |
| `F1`–`F5` | 主题：lamplight · df16 · phosphor · amber · paperwhite |
| `F6` | 窄终端下显示／隐藏侧栏 |
| `Ctrl+S` | 把这一场的日志存成文件 |
| `Ctrl+L` | 清屏（只清你本地的显示，服务端的战役还在） |
| `o` | 用系统程序打开选中的图片／音频 |
| `Ctrl+C` | 复制选中内容；没选中东西时是退出。macOS 上不一样：按住 `Option` 拖选，`Cmd+C` 复制，这两个键归终端管 |

## 6. 你可能真的会用到的指令

`.help` 会列出你们这桌所有可用的指令。玩家常用的是这些：

| 指令 | 作用 |
|---|---|
| `.r <表达式>` | 自己掷骰 |
| `.rh <表达式>` | 暗骰，只有你看得到 |
| `.ra <技能>` | 技能检定 |
| `.ra hard <技能>` | 抬高难度的检定 |
| `.rav <我的> <对方的>` | 对抗检定——`.rav 侦查 隐匿` → `Opposed Spot Hidden roll 13 Success vs Stealth roll 94 Failure: left` |
| `.st` | 看卡 |
| `.st <技能>=<数值>` | 改一项（会校验）；老的连写 `.st <技能><数值>` 也还能用 |
| `.sc <成功>/<失败>` | 理智检定，在有这套子系统的规则里——比如 `.sc 1/1d6` |
| `.ri` | 掷先攻进入顺位，或者看当前顺位 |
| `.pc` | 模组的预设角色池 |
| `.recap` | 不带剧透的前情提要 |
| `.report` | 导出这一场的战报（要这场已经有内容可导） |
| `.jrrp` | 今日人品。没有任何机制作用 |

两套写法同时生效：骰娘系的中文写法（`.ra 侦查`、`.st 力量50`、`.sc 1/1d6`）和 Avrae 系的英文写法（`/roll 4d6kh3`、`/check`）。你手熟哪套就用哪套。全量参考——包括守秘人那一侧的——在[玩家指令手册](https://1a7432.site/commands.html)。

## 7. AI 能对你做什么，不能做什么

值得知道，因为这会改变你怎么玩：

- **它没法假掷骰。** 每一次检定都走骰子引擎。守秘人负责把结果讲成故事，但结果不是它挑的。
- **它没法偷偷改你的卡。** 每一次写入都要过规则系统的校验，不管是你要求的、守秘人要求的，还是模型自己想改的。
- **NPC 没有天眼。** 一个 NPC 或者 AI 同伴，是只拿它自己的档案和卡表拼出来的，所以它不可能知道从没给过它的秘密。守秘人本身不一样：它是看得见模组秘密的（不看就主持不了谜案），我们只是要求它别说出来。最后这一点是行为约束，靠[每夜评测](https://github.com/1A7432/loreweaver/actions/workflows/redline-eval.yml)去量，不是结构上的保证。如果哪次守秘人明显把不该给的东西塞给了你，那是个值得报的 bug。
- **骰子不管剧情需不需要。** 你是会输的，而紧张感有很大一部分就来自这里。
