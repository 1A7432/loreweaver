# Rejected: the sole-active card family mechanism

- **Problem:** imported cards with multiple route/family variants tempted the
  engine into picking one "active" member automatically.
- **Verdict:** mechanism deleted outright; route curation is keeper-manual.
  Do not reintroduce.
- **Reason:** it was a single-sample mechanism (built to pass one real card)
  and semantic recall bypassed it anyway. Single-sample mechanisms get
  DELETED, not generalized — this deletion is the precedent for the standing
  no-per-card-special-casing rule.
- **Rule home:** the no-per-card rule (structural fixes with generic
  semantics only; mess in → normalized, clean out).
