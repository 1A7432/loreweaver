# Loreweaver 路线图

Loreweaver 年轻，主要由一个人在 AI 协助下开发。这是诚实的前进计划——项目当前的专注点、随后的更大方向，以及一个值得公开决策的开放设计问题。关于层级契约和铁律，请参见 [CLAUDE.md](../CLAUDE.md)。

## 志向

Loreweaver 的目标不是"用 AI 替代一个跑团主持人"，而是做 **RPG 领域的 Claude Code**。强大的 coding agent 已经很多，合格的 RPG agent 却太少太少。这里的每一层——真骰子和硬规则、靠工具调用行事的守秘人、只知道自己该知道的事的子角色、照 SKILL.md 与酒馆规范生长的扩展生态——都朝着同一个方向：让"跑好一个世界"成为 agent 的一等能力。

## 现状

确定性引擎——骰子（基于 `d20`）、CoC/DnD 成功等级、角色数学、规则验证、游戏时钟——是稳固核心，由确定性离线测试覆盖。**终端 OpenTUI 仍是主要客户端**，经 **Iroh** p2p 连接。聊天平台适配器（Discord/QQ/Telegram/飞书/OneBot）已于 2026-07-30 **主动移除**：项目的 UI 方向——声明式 `ui` 帧、实时状态量面板、深度可定制的客户端拓展层——是纯文本聊天平台在结构上就渲染不了的东西，客户端一律改走开放协议。

**v1.0.0 正式版已发布**。下文硬化清单之后，面向模组的这一层也补齐了：确定性模组变量加 TUI 实时状态量面板、导入酒馆卡的完整兼容（MVU 变量树、`<UpdateVariable>` 文本协议、QuickJS 沙箱里的完整 EJS、酒馆世界书触发语义）、能画协议 v1.7 声明式 UI 帧的沙箱事件钩子（`hooks.js`）、走 Git Release 分发的 `.lwpack` 内容包，以及发布到 npm 的协议 SDK（`loreweaver-protocol`）。在此之上是**拆卡**：导入会把一张酒馆卡拆成人物半（玩家可自带，机制被结构性剥离）和世界半（仅守秘人的 `.import … world`——钩子、变量架构、守秘人设定）；内容包给卡标注 `world` / `character` 且标签由真实检测强制；导入的变量树默认不上玩家面板、由守秘人逐路径公开；模组还能以规则包*补丁*（`extends: coc7` + 增量）的形式携带自己的规则。细节见 [plugins.md](plugins.md)、[cards.zh.md](cards.zh.md)、[hooks.zh.md](hooks.zh.md)。

## 基础设施——已完成

硬化工作刚刚落地了那些在添加广度前必须正确处理的不起眼的东西——该项目现在可以干净安装、行为正确，对小群体的运行也更安全：

- **可安装性。** Wheel 包含每个软件包和运行时数据（本地化、规则包），所以 `pip install` 可以在干净的环境中工作——而不仅限于源代码签出。
- **权限模型。** 玩家/守秘人区分现在在*每个*命令表面执行（之前仅在管理框架上保持——玩家密钥可以通过终端运行守秘人专用命令）。暴露秘密的回复——掩盖的 API 密钥、守秘人专用的传说——仅限于调用者，不向房间广播。
- **角色正确性。** 编辑技能/属性不再治疗受伤的调查员，创建派生正确的起始生命值（满血/满魔力、SAN = min(POW, SANMAX)）；每个属性设置路径都被限制在规则包范围内。
- **诚实的审核。** 内容过滤器默认关闭且无捆绑词表（可配置），文档明确说明这一点，而不是暗示内置审核。
- **真实模型红线门控。** 每晚作业让真实模型跑过 turn pipeline，按守秘人秘密的逐字/转述哨兵测量**泄漏率**，并统计**骰子优先漏骰率**，超阈值就失败。它只是一组特定模型、特定运行的回归信号，不是永久保证。（为什么必须与离线套件分开，见[下文](#离线测试-vs-真实模型质量)。）
- **传输与发布内务。** Iroh join 超时、按房间约束的 Keeper key 管理、受支持系统上的 owner-only 本地敏感文件权限、带摘要校验的发布包、稳定版/pre-release 分流、Python 3.11/3.12 CI，以及死代码清理。
- **聊天适配器——建成，然后退役。** 五个 Mock 测试覆盖的平台适配器（Discord、QQ 官方、Telegram、飞书、OneBot 11）被硬化到相当可用的程度之后被主动删除：UI 拓展方向（声明式帧、模组自绘面板）让纯文本渲染成了死胡同，与其永远端着一个二等体验，不如诚实地下线。它们验证过的跨端 RoomHub 机制保留了下来，继续支撑 CLI 与协议客户端。

## 近期

- **多人游戏抛光。** 既然权限模型已执行，收紧其余网络游玩的粗糙边角（真正的机器人循环守秘人、更丰富的迟到加入者状态），使可信人员之间的房间真正舒适。
- **配套客户端与制卡工作台——公开在即。** 原生创作的引擎侧已经落地：类型化状态量（`core.modvars`）替代了裸 MVU 树，导入的酒馆卡不只解析、真的能跑（完整 EJS、触发语义——见 [plugins.md](plugins.md)）。创作侧——不用手写 JSON 就能做 Loreweaver 原生卡和内容——已在配套桌面客户端与制卡工作台中实现，正在准备公开发布；把它们放出来就是近期要做的事。

## 更大方向——世界引擎

差异化因素是冒险*下方*的世界，而不仅仅是带骰子的聊天。长期方向：

- **高度可定制的 UI 拓展层。** 砍掉聊天适配器的原因：模组和钩子应该能**画出自己的界面**——今天是声明式 `ui` 帧（进度条、徽章、选项按钮），接下来是更丰富的模组自定义面板与客户端侧拓展点——让一个世界不只带规则和设定，还带自己的桌面陈设。渲染目标是协议客户端（TUI 与配套桌面客户端）。
- **更深世界书：** 生成型世界（不仅仅是关键字/向量检索传说）、**活生生的因果时间线**，其中事件有后果传播、**规范一致性**使守秘人无法矛盾既定事实。
- **迟到加入者赶上：** 在活动中期加入的玩家被赶上他们角色*应该*知道的信息——而不泄漏他们不应该知道的。
- **D&D Beyond 角色单导入**，与现有的 SillyTavern 卡路径并排。
- **扩大预编译平台覆盖**，超过当前的 Windows x64、macOS arm64、Linux x64/arm64 矩阵。

## 开放设计问题——守秘人的秘密住在哪里？

如今，守秘人的系统提示在（接近）完整中携带模块的守秘人池，守秘人专用工具逐字将秘密交回模型；守秘人方面的反元游戏因此是*纪律*（"不要向玩家引用这个"指示）加上确定性守秘人/玩家池分割——对子行为体（仅从它们自己的记录构建）强大，对守秘人本身较弱。

另一种方式是将秘密*保持在*基础提示之外，让守秘人通过工具按需拉取它们，使模型只会持有它刚推理的特定秘密。这以提示便利和延迟权衡较小泄漏表面。这是真正的架构分叉，值得刻意决策而不是无意漂流——欢迎输入。

## 离线测试 vs. 真实模型质量

值得明确说明，因为绿色 CI 容易被过度阅读：离线套件是确定性的，使用*脚本化*守秘人。它严格证明确定性机制——守秘人/玩家知识编辑、子行为体提示隔离、真实种子骰子、命令表面——它会捕捉这些中任何一个的回归。它**不能**证明实时模型避免泄漏显示给它的秘密，或它投掷后叙述；那些是模型行为属性，它们正是真实模型红线门（现在每晚运行）存在以测量的。读取"CI 绿色"为*引擎正确*，不是*守秘人好*。
